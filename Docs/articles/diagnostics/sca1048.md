# SCA1048: Member Nested Too Deeply

Break up code that is nested too deeply to be checked.

## Example

```cs
string Join(string a) => a + a + a + a + /* ... thousands more ... */ a;   // SCA1048: the member is not checked

string Join(string a)                                                 // OK: built in steps
{
    var builder = new StringBuilder();
    for (int i = 0; i < 5000; i++) builder.Append(a);
    return builder.ToString();
}
```

A type can be too large as well. Here the compiler infers a type for each local that is nested one level deeper than the last:

```cs
static Box<T> Wrap<[NonCopyable] T>(T value) => new(value);

var a1 = Wrap(lease);
var a2 = Wrap(a1);
// ... a thousand more ...
var a1000 = Wrap(a999);   // SCA1048: the member uses a type with more parts than the analyzer looks at
```

## How to Fix

Break up the expression, with locals or with methods of its own. For a type with too many parts, use a type with fewer parts, nested less deeply or with fewer type arguments, for example a class of its own for part of it.

## Details

A member is nested too deeply for the analyzer, which walks an expression by recursion and stops before the stack runs out. That is a chain of thousands of operators, hundreds of nested `?:`, or a thousand chained calls.

The analyzer also looks at no type with more than 512 parts, counting a part each time it appears, and at no more than 512 types in one walk over types. Only a type that the compiler infers through a long chain of generic calls, or one written out to hundreds of levels, has more parts than that. The member that uses it, or the declaration that names it, gets this warning with a text of its own.

The member or the declaration is not checked, and a copy in it gets no warning. This warning says so, where it stands, so that code that is not checked never looks clean. The other members are checked as usual.

A type nested more than 32 levels deep, or with more than 256 parts, is shown in short in every message, with its outer levels and `...` for the rest: `Box<Box<Box<Box<Box<...>>>>>`.

#### Under the Updated Rules

Under the [updated memory safety rules](../rules/updated-memory-safety-rules.md), the analyzer looks through the member for a value whose copy could break memory safety. The report is an error where it finds one, and the ordinary warning where it finds none:

| The member's code has | Report |
|---|---|
| No non-copyable type, such as a long chain of string concatenations | Ordinary warning |
| A plain non-copyable type, such as a lock guard | Ordinary warning |
| A type that is [unsafe to copy](../rules/updated-memory-safety-rules.md#types-that-are-unsafe-to-copy), or a container of one | Error |
| A type parameter marked `[NonCopyable]` or `[NonCopyable(UnsafeToCopy = true)]` | Error |
| A type parameter marked `[NonCopyable(UnsafeToCopy = false)]`, or one that is not marked | Ordinary warning |
| A call of `MemberwiseClone` or `RuntimeHelpers.GetObjectValue`, which can copy a value of any type | Error |
| A value of a type parameter marked `[NonCopyable]` or `[NonCopyable(UnsafeToCopy = true)]` used as `object` or as another type that hides it | Error |

The member's parameters and result count as well. Where the analyzer cannot finish looking, as with a type that has too many parts, the report is an error, and its message says that a type there is larger than the analyzer looks into. At a declaration it is an error unless the declaration is marked `safe` or `unsafe`. Under the current rules it is always the ordinary warning.

```cs
string Join(string a) => a + a + /* ... thousands more ... */ a;             // SCA1048: a warning

string Fill(NativeBuffer buffer, string a) => a + a + /* ... */ a;           // SCA1048: an error, if NativeBuffer is unsafe to copy
```
