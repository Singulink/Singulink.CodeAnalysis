# SCA1023: Container Used as a Type That Hides Its Values

Do not use a container of non-copyable values as a type that hides them.

## What It Means

A container is used as a type that hides the non-copyable type: `object`, `dynamic`, a base class, an interface that is not a collection, or a
type parameter that is not marked. As for `SCA1022`, variance, an override, a method group and a `foreach` can do that with no conversion
written. See [Containers and conversions](../concepts/conversions.md). It is also what a value of a marked type parameter that is converted to
such a type is reported as, and a container that is bound to a marked type parameter whose constraint is such a type: see
[Marking a type parameter](../guides/marking-a-type-parameter.md). And it is what boxing a generic struct that is non-copyable only through its type
arguments is reported as: see [Boxes](../concepts/conversions.md#boxes).

A lambda with an expression body returns the result of its call, wanted or not. `Func<object> run = () => myLock.EnterAsync();` boxes a
`ValueTask<LockGuard>` that the lambda was perhaps never meant to return, and the message says so. If the result is not wanted, give the
lambda a statement body: `() => { myLock.EnterAsync(); }` with a delegate type that returns nothing.

The messages of this rule and of `SCA1022`, `SCA1031`, `SCA1032` and `SCA1033` name a class that is a container only through what it derives
from or implements together with that type, as in `'Waiters' (a container through 'IEnumerable<Task<LockGuard>>')`.

## Example

```cs
object boxed = list;                           // SCA1023

IReadOnlyList<LockGuard> typed = list;         // OK
```
