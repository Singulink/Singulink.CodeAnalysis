# SCA1033: Container Moved Out of Something the Method Does Not Own

Do not hand over a container that the method does not own.

## What It Means

A container is passed to a `[MovedFrom]` parameter, as that of <xref:Singulink.CodeAnalysis.NonCopyable.Move*?displayProperty=nameWithType>, out of something that is not a local which the method
owns: a field, an element, a parameter that is not `[MovedFrom]` itself, or a local that something else may hold. Clearing one variable
says nothing about the other references to a container. See [Moving a value](../guides/moving-a-value.md). Move a local that holds what the method
created or got from a call. Taking a container out of a field needs a suppression: nothing can show that it is unshared. What the move
hands out is stored as well, so a read from it is reported too (`SCA1030`).

A `[MovedFrom]` parameter of a container type is not the method's own either where generic code passes a slot to it: where the member that
the method overrides or implements, or the delegate type that it is converted to, gives the parameter the type of a type parameter. Use the
container in place. A function that takes such a parameter for its own and whose body cannot be seen, such as the `Invoke` of another
delegate, is reported where it is converted.

## Example

```cs
LockGuard b = await NonCopyable.Move(ref _cached);   // SCA1033: whoever else has the task can await it too

var pending = myLock.EnterTaskAsync();
LockGuard a = await NonCopyable.Move(ref pending);   // OK: the method's own
```
