# SCA1031: Return of a Container the Method Does Not Own

Do not return a container that the method does not own.

## What It Means

A method, a local function, a lambda or an operator returns, or yields, a container that something else still holds, an array or an
<xref:System.ArraySegment`1> included. Callers take the result of a call for a new value, so every caller would read its non-copyable values as new.
A local counts as held by something else after any use that is not on the list of what leaves it the method's own, and the message names
that use. See [Returning a container](../concepts/returning-containers.md). Return a container that the method created and handed to nothing that keeps
it, or mark the method `[return: Borrowed]`.

It is also what a delegate is reported as that would hand out a stored container as the result of a call: one that is created from a
method group of a member which hands out what its container holds, or, in generic code, from a function that returns a value of a marked
type parameter. See [Marking a type parameter](../guides/marking-a-type-parameter.md). Use a delegate type whose return value is marked
`[return: Borrowed]`.

And it is what a conversion that is not written is reported as, of a class that derives from a framework container, or of a type whose
own code decides what it holds, to the container: the covariant return of an override, a method group whose method returns the derived
class for a delegate that returns the container, and a variant type argument that goes from the one to the other.

## Example

```cs
Task<LockGuard> GetCachedAsync() => _cached;   // SCA1031: every caller would get the same task

List<LockGuard> Build()
{
    var list = new List<LockGuard>();
    list.Add(myLock.Enter());
    return list;                               // OK: the method's own
}
```
