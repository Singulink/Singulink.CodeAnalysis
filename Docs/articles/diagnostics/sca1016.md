# SCA1016: Use After a Hand-off

Do not use a variable after its non-copyable value was handed over.

## Example

```cs
var guard = myLock.Enter();
TakeGuard(guard);                              // hands the guard over, and 'guard' still holds it
guard.Dispose();                               // SCA1016: TakeGuard got a copy, since 'guard' is used here

var other = myLock.Enter();
Console.WriteLine(other.Id);                   // OK: used before the hand-off
TakeGuard(other);                              // OK: the last use of 'other', so the guard moves
```

## How to Fix

- **Use the variable only before the hand-off.** Read what you still need first, so that the hand-off is the last use of the variable.
- **Hand over a reference** (`ref`, `in`, `ref readonly`) where the receiver only uses the value, and keep the value in the variable.
- **Hand over what <xref:Singulink.CodeAnalysis.NonCopyable.Move*?displayProperty=nameWithType> takes out of the variable,** which leaves the default value behind. A later use then finds nothing to release.
- **In a `catch`,** store the value at the end of the `try` block, after everything that can throw, or hand it over after the `try` statement. See [Cleaning Up When Something Throws](../guides/cleanup-when-throwing.md).
- **For a `using` statement over a variable,** declare the variable in the statement, or write a `using` declaration with a new value. See [A Using Statement Over a Variable](#a-using-statement-over-a-variable).

## Details

A local or a by-value parameter is a new value at its [last use](../rules/last-use.md), so handing it over there moves it. Where the code uses the variable again after a read by value, the read was not the last use, and it copied the value. The analyzer reports the copy at the first use after the read, where the code goes wrong, and gives the read as an additional location. The message says how the value was handed over: by an assignment, a call, a tuple, a conversion or a `return`.

#### Which Uses Are Reported

- **The first use on each path.** A use on a later line of the same path is not reported again, and a use that two hand-offs reach is reported once.
- **A use that is itself a hand-off** is reported, and is the hand-off for the uses that follow it.
- **An assignment of the whole variable** gives it a new value, so a use after it is fine.
- **A `catch`, a `finally` or an exception filter** that uses the variable can run after a read in its `try` block, and the message says so. A member that throws may have taken the value, so this holds after every hand-off to a member. A store at the end of the `try` block, followed by nothing that can throw, is the exception: see [Commit at the End of a Try Block](../rules/commit.md).

#### A Using Statement Over a Variable

A `using` statement over a variable takes a copy of its value, which it disposes at its end. A use of the variable inside the statement, or after it, comes after that hand-off. Declare the variable in the statement, or write a `using` declaration with a new value:

```cs
var guard = myLock.Enter();
using (guard)                                  // takes a copy, which it disposes at its end
    Console.WriteLine(guard.Id);               // SCA1016: 'guard' still holds the guard

using (var inside = myLock.Enter())            // OK: the statement declares the variable
    Console.WriteLine(inside.Id);

using var held = myLock.Enter();               // OK: a 'using' declaration with a new value
Console.WriteLine(held.Id);
```

#### Members That Take a Value Only Where They Return True

Some members take the value only where they return true, as `ChannelWriter<T>.TryWrite` does. Their [symbol list](../rules/symbol-list-format.md#borrowswhen) entries say so, and a use on the branch where the member returned false is no use after the hand-off:

```cs
if (!_writer.TryWrite(lease))
    lease.Dispose();                           // OK: TryWrite has not taken the lease here
```

This holds only where the result of the call goes straight into a condition. Which members of the framework take a value only where they return true: [Built-in Framework Symbol List](../rules/framework-symbol-list.md#members-that-take-a-value-only-where-they-return-true).

#### Copies That Stay Where They Are Made

Some copies have no use of their own to be reported at. They keep the ID of the copy (SCA1001, SCA1002 or SCA1003), at the read:

- a read that is its own later use, the next time round a loop;
- a read of a variable that is never moved from, such as a field, a `ref` parameter, a captured variable or a `using` variable;
- a read in an exception filter, which is never a last use.

A read out of a task or a list in a variable is SCA1030, at the read. [Use After a Hand-off](../rules/last-use.md#use-after-a-hand-off) has the full list.
