# SCA1020: Member of an Unmarked Generic Not on the Symbol List

Do not use a member of an unmarked generic with a non-copyable type.

## Example

```cs
var list = new List<LockGuard>();              // OK: on the symbol list
list.Add(myLock.Enter());                      // OK: on the symbol list
LockGuard[] all = list.ToArray();              // SCA1020: not on the symbol list, it copies
```

## How to Fix

- **Mark the type parameter** `[NonCopyable]`, if the generic is yours. Its body is then checked.
- **Add the member to a [symbol list file](../rules/symbol-list-format.md)** if it makes no copy and the generic is not yours to mark. The message gives the line to add. See [Symbol List](../guides/symbol-list.md#adding-a-member-of-a-library).
- **Avoid the use**, if the member copies, as `ToArray` does.

## Details

A member of a generic is used with a non-copyable type bound to a type parameter that is not marked, and the member is not on the [symbol list](../rules/symbol-list-format.md). The analyzer assumes that code which cannot see that a type is non-copyable copies it. See [Generics That Are Not Marked](../rules/marked-type-parameters.md#generics-that-are-not-marked).

A type parameter that is marked in an assembly that was not built with the analyzer counts as not marked, since nothing checked its generic. The message says so, and the fix is then a symbol list entry, or avoiding the use. See [Code Not Built With the Analyzer](../rules/unchecked-code.md).
