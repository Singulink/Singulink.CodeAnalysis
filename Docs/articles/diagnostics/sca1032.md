# SCA1032: Container Parameter Kept Without the Kept Mark

Mark a container parameter that the method keeps.

## What It Means

A method keeps a container that it was given through a parameter which is not marked `[Kept]`: it assigns it to a field, an element or a
property, alone or inside a tuple, writes it through a reference, captures it in a lambda or a delegate, or passes it on to something
that keeps it. Or it uses the parameter in a way that is not on the list of what is known to leave the container with the caller,
which is reported with a text of its own. So is passing it to a listed member through a parameter whose type mentions a type
parameter that is not marked: nothing checks what such a member does with the container, and the text names the entry that says
it only `borrows`. A caller takes a container that it passes to be its own afterwards. It is reported once for
a parameter. See
[Keeping a container that is passed in](../concepts/keeping-containers.md). Mark the parameter `[Kept]`, or do not store the
container.

It is also reported for an iterator that uses a container parameter, and for an `async` method that uses one on a path after an `await`:
both go on after they have returned to their caller. Mark the parameter `[Kept]`, or use the container only before the first `await`.

## Example

```cs
void Register(List<LockGuard> list) => _all = list;          // SCA1032: keeps it

void Register([Kept] List<LockGuard> list) => _all = list;   // OK
```
