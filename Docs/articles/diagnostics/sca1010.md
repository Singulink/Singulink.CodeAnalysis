# SCA1010: Field in a Copyable Struct or a Record

Do not declare a field of a non-copyable type in a copyable struct or a record.

## Example

```cs
struct Session(LockGuard guard) { public void Close() => guard.Dispose(); }   // SCA1010: 'guard' is a field of a copyable struct

[NonCopyable]
struct Session(LockGuard guard) { public void Close() => guard.Dispose(); }   // OK
```

## How to Fix

- **Mark the struct `[NonCopyable]`** too, so that it is not copied either. Where the field's type is unsafe to copy, the message says to mark it `[NonCopyable(UnsafeToCopy = true)]`, which also keeps the field from getting [SCA1017](sca1017.md).
- **Make it a class** that is not a record.

## Details

A struct that is not itself non-copyable has a field of a non-copyable type, or a record has one. Copying the struct would copy the field, and a record copies its fields in `with` and in the members that the compiler writes for it.

- A parameter of a copyable struct's primary constructor that the struct's members use is such a field as well.
- A type parameter marked `[NonCopyable]` does not stand in for the mark on the struct. `Pair<int>` of a struct `Pair<[NonCopyable] T>` that has a `LockGuard` field is copyable, and copies the guard. A field of the type parameter itself, or of a type over it such as `T?`, needs no mark.
- A static field gets no warning: no copy of a struct or a record copies it.
