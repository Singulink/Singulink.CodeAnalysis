# SCA1043: Type That Does Not Stay Erasable

Keep a type that derives from an erasable type erasable.

## What It Means

A type derives from an erasable type, or implements one, and adds a way out of it: a base class or an interface with bodies that are not
checked for the non-copyable type that it receives, or an interface that has a reference type which mentions the non-copyable type in a
position that is covariant in effect (`out`, or `in` inside `in`). See [Variance and erasable types](../concepts/variance-and-erasable-types.md). Mark the
type parameter of the base type, constrain the type parameter to `struct`, or do not derive from the erasable type.

## Example

```cs
class Bag<[NonCopyable] T> { }

class SortedBag<[NonCopyable] T> : Bag<T>, IProducer<T> { }                   // SCA1043: with a list of guards as T, the object
                                                                              // could be converted on to IProducer<object>

class GuardBag<[NonCopyable] T> : Bag<T>, IProducer<T> where T : struct { }   // OK: variance needs a reference type
```
