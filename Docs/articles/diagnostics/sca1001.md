# SCA1001: Copy by Assignment

Do not copy a non-copyable value by assignment.

## Example

```cs
LockGuard copy = _guard;                       // SCA1001: a copy of the field

ref LockGuard alias = ref _guard;              // OK: a reference
LockGuard taken = NonCopyable.Move(ref _guard); // OK: moved, and the field is left empty
```

## How to Fix

- **Refer to the value** with a `ref` local instead of copying it.
- **Move it out** with <xref:Singulink.CodeAnalysis.NonCopyable.Move*?displayProperty=nameWithType>, which leaves the default value behind. See [Moving Values](../guides/moving-values.md).
- **Make the assignment the last use** of a local, by reading what you still need first. See [Fixing Common Warnings](../start/fixing-common-warnings.md#variable-that-is-used-after-it-was-handed-over).
- **For a `foreach`**, loop with a `ref` variable over a span of the elements, as the message says.

## Details

A variable, a field or an array element is assigned a stored value, which copies it. That includes:

- a variable that a pattern, a deconstruction or a `foreach` declares;
- a value that is taken out of a box;
- the copy of a stored value that a deconstruction or a `foreach` makes before it calls a `Deconstruct` that is not `readonly`.

A local or a by-value parameter gets no warning at its [last use](../rules/last-use.md). Where the code uses the variable again after the read, the warning goes to that later use instead ([SCA1016](sca1016.md)). A read inside an exception filter is never a last use, and gets its warning where it is.

Two more cases get a warning whatever the value is, even a new one:

- a second variable that a pattern declares for a value which it has given to another variable: see [One Value Goes to One Variable](../rules/patterns.md#one-value-goes-to-one-variable);
- the variable of a `switch` clause after a clause with a `when` that could have taken the same value: see [Clauses of a Switch](../rules/compiler-copies.md#clauses-of-a-switch).
