# SCA1001: Copy by Assignment

Do not copy a non-copyable value by assignment.

## What It Means

A variable, field or array element is assigned the value of a stored value, which copies it. This includes a variable that a pattern, a
deconstruction or a `foreach` declares, a value that is taken out of a box, and the copy of a stored value that a deconstruction or a
`foreach` makes before it calls a `Deconstruct` that is not `readonly`. Assign a reference (`ref var r = ref guard;`), a new value, or
[move](../guides/moving-a-value.md) the stored value. A local or a by-value parameter is not reported at its
[last use](../concepts/last-use.md). Where it would be at its last use but for a `catch`, a `finally` or an exception filter that
still uses it, the message says so. For the variable of a `foreach` the message says what to write:
`foreach (ref var guard in ...)` over a span of the elements. A read inside an exception filter is never a last use. A second variable that a pattern declares for a
value which it has given to another variable is reported whatever the value is, and so is the variable of a `switch` clause after a clause
with a `when` that could have taken the same value: see [Patterns, deconstruction and tuples](../concepts/patterns.md) and
[Where the compiler uses one value twice](../concepts/compiler-copies.md).

## Example

```cs
LockGuard copy = _guard;                       // SCA1001: a copy of the field

ref LockGuard held = ref _guard;               // OK: a reference
LockGuard taken = NonCopyable.Move(ref _guard); // OK: moved, and the field is left empty
```
