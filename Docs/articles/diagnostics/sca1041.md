# SCA1041: MovedFrom Used Wrongly

Use `[MovedFrom]` on a 'ref' parameter that the method resets.

## What It Means

`[MovedFrom]` is on something that is not a `ref` parameter, or the method can leave with the parameter read and not yet assigned, or it can
read the parameter a second time before it is assigned, or between the read and the assignment it runs more than reads and writes of its
own locals, or it makes the parameter refer to something else (`value = ref other;`). Passing the parameter on by `ref` to a parameter that
is not `[MovedFrom]` is not an assignment. Where what runs is a read or a write through a reference that can be a null reference, the
message names the reference and says to check it first, with `NonCopyable.ThrowIfNullRef(in x)`, or `in this` for `this` in a struct,
or with a method whose parameter is marked `[NotNullRef]`, which counts only in an assembly that was built with the analyzer: see
[A reference that is known to refer to something](../guides/null-references.md). The message of a value that is
stored at the end of a `try` block and followed by such a read or write says the same.

`[MovedFrom]` on a parameter of a primary constructor is reported where it is declared: `class Session([MovedFrom] ref LockGuard guard)`.
The code of a primary constructor is the initializers of the type and the call of the base constructor, which have no order in which
the parameter could be read and then assigned. Declare an ordinary constructor, or move the value out in the one initializer that
takes it: `public LockGuard Held = NonCopyable.Move(ref guard);`. As a guard against a member of some other kind whose paths are not
followed, a `[MovedFrom]` parameter of a member that has code and was not followed is reported at the end of the build.

It is also reported where a method leaves something in a `[MovedFrom]` parameter that its caller cannot own: a container that something
else holds in a parameter of a container type, and, in a generic move, anything but `default` or what the method read from its
`[MovedFrom]` parameters, in what it returns or in what it leaves behind. See [Moving a value](../guides/moving-a-value.md).

## Example

```cs
static void Replace([MovedFrom] ref LockGuard slot, ref LockGuard old)
{
    old = slot;
    slot = Create();                // SCA1041: if Create throws, 'old' and 'slot' hold the same guard
}

static void ReplaceSafely([MovedFrom] ref LockGuard slot, ref LockGuard old)
{
    LockGuard fresh = Create();     // what can throw comes first
    old = slot;
    slot = fresh;                   // OK: the last use of 'fresh'
}
```
