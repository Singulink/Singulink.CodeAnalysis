# SCA1008: MemberwiseClone of a Class That Can Be Derived From

Do not call MemberwiseClone on a class that another assembly can derive from.

## What It Means

<xref:System.Object.MemberwiseClone> clones the object that it is called on, whatever its class. The class of the receiver has no field
of a non-copyable type, but it can be derived from in another assembly, where a derived class can hold a non-copyable value that the clone
would copy. A class can be derived from there if it, or a class of the same compilation that derives from it, is not sealed, can be
reached from outside its assembly together with every type that contains it, and has a constructor that a derived class there can call. A
base class whose constructors are all internal can be derived from in this way through a public class that derives from it. A nested
class that is protected can be reached only from a class that derives from the class that contains it, so only where that class can be
derived from in another assembly. An assembly with `InternalsVisibleTo` counts its internal types and constructors as reachable. A
file-local class is never reachable.

A derived class of the same compilation that has such a field is reported as the definite copy that it is (`SCA1005`), and this finding
has an ID of its own so that turning it off leaves those standing.

## What to Do

There are three ways out:

- **Seal the class.** A sealed class has no derived class. This is not open to an abstract class, nor to one that is meant to be derived
  from.
- **Do not call MemberwiseClone.** Copy the fields of the class in a constructor that takes the object to copy, and let each derived
  class do the same for its own fields, calling the one of its base. Each class then copies only what it declares, and a derived class
  that holds a non-copyable value decides itself what its copy gets, where the analyzer checks it.
- **Suppress the finding.** The suppression is then a rule for every class that derives from this one: none of them may hold a
  non-copyable value, since the clone would copy it. For a class that is meant to be extended and cloned with MemberwiseClone, this is
  the expected answer. Write the rule into the documentation of the class, where the authors of derived classes read it.

A project none of whose classes are meant to be derived from with non-copyable values can turn the rule down for the whole project in
`.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SCA1008.severity = none
```

## Example

```cs
public class Options
{
    public Options Copy() => (Options)MemberwiseClone();        // SCA1008: another assembly can derive from Options
}

public sealed class SealedOptions
{
    public SealedOptions Copy() => (SealedOptions)MemberwiseClone();   // OK: no derived class
}

public class Settings
{
    private readonly string _name;

    public Settings(string name) => _name = name;

    protected Settings(Settings other) => _name = other._name;   // OK: copies only what Settings declares

    public virtual Settings Copy() => new(this);
}

public class LockedSettings : Settings
{
    private LockGuard _guard;

    public LockedSettings(string name, LockGuard guard) : base(name) => _guard = guard;

    protected LockedSettings(LockedSettings other) : base(other) { }   // the copy gets no guard: this class decides

    public override Settings Copy() => new LockedSettings(this);
}
```
