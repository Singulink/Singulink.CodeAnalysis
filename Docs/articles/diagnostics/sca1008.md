# SCA1008: MemberwiseClone of a Class That Can Be Derived From

Do not call MemberwiseClone on a class that another assembly can derive from.

## Example

```cs
public class Options
{
    public Options Copy() => (Options)MemberwiseClone();        // SCA1008: another assembly can derive from Options
}

public sealed class SealedOptions
{
    public SealedOptions Copy() => (SealedOptions)MemberwiseClone();   // OK: no derived class
}

public class Settings
{
    private readonly string _name;
    public Settings(string name) => _name = name;
    protected Settings(Settings other) => _name = other._name;   // OK: copies only what Settings declares
    public virtual Settings Copy() => new(this);
}

public class LockedSettings : Settings
{
    private LockGuard _guard;
    public LockedSettings(string name, LockGuard guard) : base(name) => _guard = guard;
    protected LockedSettings(LockedSettings other) : base(other) { }   // the copy gets no guard: this class decides
    public override Settings Copy() => new LockedSettings(this);
}
```

## How to Fix

There are three ways out:

- **Seal the class.** A sealed class has no derived class. This is not open to an abstract class, nor to one that is meant to be derived from.
- **Do not call MemberwiseClone.** Copy the fields of the class in a constructor that takes the object to copy (see [Copying in a Constructor](#copying-in-a-constructor)).
- **Suppress the warning.** The suppression is then a rule for every class that derives from this one (see [Suppressing](#suppressing)).

## Details

<xref:System.Object.MemberwiseClone> clones the object that it is called on, whatever its class. The class of the receiver has no field of a non-copyable type, but it can be derived from in another assembly, where a derived class can hold a non-copyable value that the clone would copy. So this warning can appear in a project that copies nothing.

#### What Can Be Derived From in Another Assembly

A class can be derived from in another assembly if it, or a class in the same compilation that derives from it, meets all three of these:

- it is not sealed;
- it can be reached from outside its assembly, together with every type that contains it;
- it has a constructor that a derived class there can call.

| Case | Counts? |
|---|---|
| A base class whose constructors are all internal, with a public class that derives from it | Yes, through that public class |
| A nested class that is protected | Only where the class that contains it can be derived from in another assembly |
| An internal type or constructor in an assembly with `InternalsVisibleTo` | Yes: it counts as reachable |
| A file-local class | Never |

Where a derived class in the same compilation has such a field, the call gets a warning as the definite copy that it is ([SCA1005](sca1005.md)). This warning has an ID of its own so that you can turn it off and still keep those warnings.

#### Copying in a Constructor

Copy the fields of the class in a constructor that takes the object to copy, and let each derived class do the same for its own fields, calling that constructor of its base class. Each class then copies only what it declares. A derived class that holds a non-copyable value then decides for itself what its copy gets, in code that the analyzer checks.

#### Suppressing

A suppression is a rule for every class that derives from this one: none of them may hold a non-copyable value, since the clone would copy it. For a class that is meant to be extended and cloned with MemberwiseClone, this is the expected answer. Write the rule into the documentation of the class, where the authors of derived classes read it.

If none of a project's classes is meant to be derived from by a class that holds non-copyable values, the project can turn the rule down in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.SCA1008.severity = none
```
